Revertir cada método y devolver la tarjeta a su estado original (modo managed/estación) junto con la conectividad normal de red:

#### 1. Reversión para el método airmon-ng
Se utiliza la instrucción de parada indicando el nombre de la interfaz en modo monitor (habitualmente renombrada a `wlan0mon`):
```bash
sudo airmon-ng stop wlan0mon
```
[[2.1.3 Habilitar modo monitor manualmente#1. Con airmon-ng (Automatizado / ==Suite Aircrack-ng==)]]

---
#### 2. Reversión para el método heredado iwconfig
Se baja la interfaz, se asigna el modo administrado y se vuelve a encender:
```bash
sudo ifconfig wlan0 down
```
```bash
sudo iwconfig wlan0 mode managed
```
```bash
sudo ifconfig wlan0 up
```
[[2.1.3 Habilitar modo monitor manualmente#2. Con `iwconfig` (Método heredado / Wireless Extensions/ ==Ifconfig==)]]

---
#### 3. Reversión para el método `iw` (Interfaz original)
Se apaga la interfaz, se cambia el tipo a `managed` y se vuelve a levantar:
```bash
sudo ip link set wlan0 down
```
```bash
sudo iw dev wlan0 set type managed
```
```bash
sudo ip link set wlan0 up
```
[[2.1.3 Habilitar modo monitor manualmente#3. Con `iw` (Estándar moderno `nl80211`)]]

---
#### 4. Reversión para el método de interfaz virtual (`mon0`)
Simplemente se da de baja y se elimina la interfaz virtual creada, dejando intacta la interfaz base:
```bash
sudo ip link set mon0 down
```
```bash
sudo iw dev mon0 del
```
[[2.1.3 Habilitar modo monitor manualmente#4. Creando una interfaz virtual con `iw` (Sin alterar la original)]]

---
### Paso final recomendado (Restauración de conectividad)
Si usaste `airmon-ng check kill` o los servicios de red se detuvieron al cambiar de modo, reinicia el gestor de red para que el sistema vuelva a detectar y conectarse a redes Wi-Fi:
```bash
sudo systemctl restart NetworkManager
```
